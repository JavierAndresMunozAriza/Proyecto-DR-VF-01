## 3. Verified OK

- Engine builds with 0 warnings (`-Wall -Wextra -Wpedantic -Wconversion -Wshadow -Wdouble-promotion`, gcc 15.2). 11 tests, 1596 checks, 0 failed, plain and under `-fsanitize=address,undefined -fno-sanitize-recover=all` (also float-divide-by-zero, float-cast-overflow): no leak, no UB, exit code 0, nothing on stderr. `make test`, `make debug`, `make depend`, `make clean` work; build artefacts are git-ignored (`.gitignore:36-39`).
- `grow_capacity`: clamps to 65535, doubling cannot overflow `uint32_t`, `realloc` failure keeps the old block; 65535-vertex test passes under ASan.
- Half-open boundary rule: for axis-aligned rectangles (all 8 boundary cases) and for 2.42 M integer-grid points on 20 000 random star polygons, ray casting == winding == exact integer reference (0 differences). CW/CCW order, concave L-shape, NaN/Inf point, NULL arguments, fewer than 3 vertices, uninitialised engine, polar point (lat 90) and +/-180 longitude behave as documented. Haversine antipode clamp works (361 x 181 grid, no NaN).
- GPIO map: every GPIO number and signal name in BOOT_SEQUENCE, FSM_DESIGN, MVP_DEFINITION, REQUIREMENTS, PROJECT_CONTEXT section 4.3 and ARCHITECTURE matches `pinout.md` (I2C 8/9, SPI 10-13, BUSY 14, DIO1 6, NRESET 5, RXEN 42, TXEN 47, INT1 4, BUTTON 7, GNSS 17/18/21, USB 19/20, XTAL 15/16, CHRG 41, OPTO 1, BUZZER 2, LEDs 38-40). Wake pins GPIO4/6/7 and held pins GPIO1/5/10/14 are all RTC GPIO (0-21); Zephyr exposes `ESP32_GPIO_SLEEP_HOLD_EN` (`include/zephyr/dt-bindings/gpio/espressif-esp32-gpio.h:84`).
- Addresses: LSM6DS3TR-C WHO_AM_I = 0x6A (DS reg table; p60) and I2C address 0x6A with SDO/SA0 to GND; MAX17048 7-bit address 0110110 = 0x36 (DS I2C section).
- IMU register values are correct: CTRL1_XL 0x10 = 12.5 Hz/+-2 g; CTRL6_C 0x10 = XL_HM_MODE bit 4; TAP_CFG 0x58 bit 7 INTERRUPTS_ENABLE; WAKE_UP_THS 0x5B 6 bits, 1 LSb = FS/2^6 = 31.25 mg (0x10 = 0.5 g); WAKE_UP_DUR 0x5C WAKE_DUR 2 bits; MD1_CFG 0x5E bit 5 INT1_WU (DS p60-66, 88-92); 9 uA at 12.5 Hz low power (DS p24); turn-on 35 ms. MVP threshold formula `x*32+0.5` matches 1 LSb = 31.25 mg.
- MAX17048: VCELL 0x02, 78.125 uV/cell; hibernation 3 uA typ with VRESET.Dis = 1, 4 uA with Dis = 0; 45 s hibernate sample period (DS electrical table, register table).
- MAX-M10S: standby current 46 uA at V_IO 3.3 V (DS p13), hot start 1 s / cold 23-28 s, no autobaud documented, default 9600 bd.
- SX1262 pad states in Sleep match the pinout hold rules: NSS "IN" (hold high), NRESET "IN PU" (do not drive low), BUSY "HIZ PU" 20 kOhm (DS Table 8-3 p54, p52). Zephyr `semtech,sx1262` binding covers busy/reset/DIO1/RXEN/TXEN/DIO2-as-TX/DIO3-TCXO, so both antenna-switch options in pinout.md are expressible.
- GPIO47/GPIO48 stay at 3.3 V on the N16R8 module: the 1.8 V note applies only to ESP32-S3R16V/R16VA modules (WROOM-1 DS pin table note c, Table 2 footnote 7; ESP32-S3 DS note 4).
- Zephyr availability: LoRa `semtech,sx1262` (sx126x driver), fuel gauge `maxim,max17048` (read-only), GNSS `u-blox,m10` (UART, UBX, NAV-PVT), ESP32-S3 board `esp32s3_devkitc` with `esp32s3_wroom_n16r8.dtsi` present, deep sleep via `sys_poweroff()`/EXT1 and `retained_mem` (ZP sample `samples/boards/espressif/deep_sleep`), watchdog API `wdt_*`. IMU: LSM6DS3TR-C has no own driver in ZP; the Seeed XIAO BLE board describes it at 0x6A (`boards/seeed/xiao_ble/xiao_ble_nrf52840_sense.dts:40`) and ST's `lsm6dsl` driver (compatible family) only triggers on data-ready (`lsm6dsl_trigger.c:51`), so wake-on-motion needs the planned custom register driver (the docs already say so).
- Report boot budget adds up (1.2+1.8+1.5+0.5 = 5.0 s). FSM state names and transitions are consistent between FSM_DESIGN.md text and its mermaid diagram. Low-battery guard numbers (3.3/3.4 V, 45 s stale VCELL) agree across FSM_DESIGN, pinout, POWER_BUDGET.
